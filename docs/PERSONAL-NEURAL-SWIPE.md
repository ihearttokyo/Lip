# Approved personal vocabulary in neural swipe — prospective contract

This is a feature increment against the unchanged English benchmark/rubric, not
a Gboard-superiority or9.2 acceptance claim. Synthetic paths are component controls,
never the frozen human development/confirmation sets. The physical-phone hold,
paired human study and actual device/editor/energy gates are unchanged.

## Frozen candidate policy, before component decode outcomes

- Reuse the exact pinned MIT swipe model and native beam implementation. No new
  weights, training data, geometry matcher/fallback or model download. A gesture
  invokes the neural model once against one combined lexicon, not two engines.
- Preserve every admitted base lexeme and its prior. Source/base asset verification
  remains capped at250,000; model/base/vendor hashes and licence notices stay fixed.
- Merge up to100,000 approved portable records and200 manual records. No silent
  capacity truncation: the native/Kotlin union cap is350,200. Existing48-character,
  ASCII/apostrophe grammar and40-collapsed-key-path bounds remain unchanged.
  Unsupported phrases/scripts/long paths stay stored and are counted, not learned.
- Manual display spelling wins, then the first approved portable spelling. Existing
  base frequencies stay unchanged. OOV priors are fixed prospectively at
  `128 + min(127, floor(log2(weight))*8)`; manual weight is1. Reimport never sums
  weights. Do not tune these priors against observed component/holdout outcomes.
- One cached immutable union/native engine per stable process mutation epoch.
  Close the prior native engine before opening the new one. No per-gesture100k
  decryption while an unchanged cache is valid. Source/open failures stay closed
  for the same context; a newly eligible reopened context may retry once, never
  a background loop or stale/base-only fallback.
- A CPU-only shared gate invalidates unclaimed work BEFORE dictionary mutation,
  including failed/equal writes. No private IO, editor IPC or observer runs under
  that gate. Cursor IPC precedes the final one-use ownership claim; an already-
  admitted dispatch may finish once after a later mutation, never retry ambiguously.
- Only visible, interactive, unlocked ordinary IME context admits personal reads.
  Hide/start/finish/new-view/screen-off revoke tokens. Password/incognito/no-learning
  contexts must neither preload personal vocabulary nor receive late results.

## Fixed Unicode transport

Android now uses the same version/hash-pinned Unicode16 tables as Mac, rather
than refusing the entire portable dictionary on newer OS Unicode tables. The
Java resource is small (387,200bytes), not a model/runtime. Original Unicode and
CPython notices accompany it; regeneration checks both copies. Actual Android
ClassLoader loading remains a separate packaged-artifact check, not proven by
JVM resource lookup alone. New Unicode17-only characters are still refused by
v1's Unicode16 contract; no silent migration or locale-lowercase substitution.

## Prospective component controls (not accuracy scoring)

Preserve base/frequencies/display precedence,100k/no-truncation limits, grammar,
known/OOV metadata, idempotent weights and expected capacity refusal. Exercise
real pinned table resources and shared Python16 NFC/fullfold vectors. Native
controls use the full admitted base plus approved synthetic words **Jaredium** and
**Sampleton**, unchanged synthetic centre paths, geometry/cancel/epoch refusal
and exact display resolution. Any failed control is retained; no prior/word-set
retuning is permitted to rescue a result. A successful synthetic decode is not a
human held-out word, measured physical latency/energy or superiority result.

Full release qualification still requires the original Gboard baseline, actual
phone/editor/private-field tasks and independent>=9.2 without rounding. No release
is authorized by this source increment or by passing a build/manifest/test counter.
