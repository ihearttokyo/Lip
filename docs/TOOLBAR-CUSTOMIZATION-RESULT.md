# Toolbar customization — scoped source and emulator evidence

29October2026. Requirements remain in the unchanged [v1 contract](TOOLBAR-CUSTOMIZATION.md).
This is not full Gboard parity, a release, a physical test or a product score.

## Implemented path

Keyboard preferences → **Customize toolbar** selects and orders the five middle
shortcuts. Tools and microphone remain the endpoints. Emoji, local GIFs,
clipboard, owned Undo/Redo, text editing and local sticker packs use existing real
consumers. The Agent/future-translation default placeholder remains unavailable
without actual transport admission; configuration never admits one.

The seven-position preview uses the consumer's mapping and geometry but has no
consumer callbacks. Move up/down alternatives, explicit Save, Reset default and
Reload confirmed toolbar are visible scrollable controls. Choosing an action
already present swaps positions instead of creating duplicates. Unknown/corrupt
initial data disables the middle consumer actions until explicit Save/Reset;
Tools/microphone remain reachable. Failed or stale-revision saves retain confirmed
mapping authority. No account, typed content or clipboard data is stored here.

CPU-only original-contact reservation precedes external metadata queries. Mapping,
render, editor, caret, composition, hidden-view and contact ownership are checked
again before dispatch. A physical toolbar stream outlives a consumed long action
and blocks a second pointer through the final lift; an old root cannot clear a
new root's stream. These source/pure controls do not replace actual multitouch,
long-press, accessibility or receiving-editor qualification.

## Actual checks

- Offline ARM64 app/test APK build, lint and JUnit pass:776 cases,758 executed,
  18 explicit skips, zero failures/errors. All18 new focused toolbar cases execute.
- Bounded independent source review passes after contact/hidden/stale-root repairs.
- Actual normal Settings path opens the black/glass customizer. A microphone
  **preview** tap stays in configuration; no recorder or permission UI appears.
  Source confirms no preview consumer callback; this observation alone is not a
  system-wide microphone audit.
- Actual Choose → Text editing, Move down, replace GIF with Stickers → Save stores
  `EMOJI,TEXT_EDITING,STICKERS,CLIPBOARD,UNDO`. The actual IME shows that order;
  direct Text editing and Stickers taps open their existing pages. Return restores
  typing. No edit, attachment or audio-record action was requested in those pages.
- Actual Reset from a second customizer restores default persisted IDs. Returning
  to an older still-open customizer displays its old draft; attempting its stale
  Save refuses with an explicit Reload message and leaves confirmed preference
  bytes unchanged. A fresh ordinary editor shows the default toolbar again.
- Separate owned receiver observations retain unchanged baseline text and zero
  commitContent, Enter or editor-action calls during these navigation checks.

These checks use the isolated owned API36 ARM64 emulator and a frozen development
APK, with guest Wi-Fi/data disabled and synthetic editor/pack data only. Runtime
identity still precedes this feature's next version reservation. No installed Mac,
physical Xiaomi, live provider, private history, model retrieval or full release
was used. Existing first-show, text-editing privacy/selection and other product
failures remain in their own evidence; this feature does not erase them.

## Not yet qualified

Complete narrow/landscape/one-hand geometry and hit targets, actual screen-reader
and hardware-key activation, physical long-press/multitouch/lifecycle matrix,
corrupt-on-disk and true write-failure runtime controls, unsaved-change/cancel and
all supported destination variants remain open. Pure/schema tests do not certify
those real paths. Direct/background agent sending, future translation and the
full independent9.2 gate remain separate.
