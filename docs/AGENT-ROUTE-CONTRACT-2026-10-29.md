This is a bounded feasibility observation, not provider admission or a claim that
all possible integrations are impossible. No provider was launched, prompt sent,

## ChatGPT desktop

The official [desktop command contract](https://learn.chatgpt.com/docs/app/commands)
was searched and opened on29October2026 JST. `codex://new?...` and
`codex://threads/new?...` can initialize a composer. The documented prompt flow
requires the user to submit it; it is not automatic/background sending. No effort
or model parameter is established by that contract. This cannot satisfy Jared's
explicit direct/background-only request and is not admitted as a draft fallback.

Read-only installed application metadata: ChatGPT26.1023.50603,
`com.openai.codex`, declares `codex`, `http`, `https`; no NSServices are declared.
Claude1.34493.1, `com.anthropic.claudefordesktop`, declares `claude` plus an
MSAL authentication callback; no NSServices are declared. A registered URL scheme
is not a prompt-send/account/effort contract. No callback tokens or private files
were inspected; no URL was opened. These observations do not rule out another
supported provider interface.

## Admission requirements remain open

A real route needs supported exact-payload direct/background sending, verified
recipient/new-chat identity, requested effort capability, user-approved account
and cost/auth scope, and real consumer acknowledgement. Submission uncertainty
must not trigger automatic retries, cursor insertion or another provider. Pro is
a desired mode, not assumed to be an API reasoning value. Existing subscription
access is not authorization to use an API or third-party account token.

macOS shortcut/coordinator/settings implementation may be tested with synthetic
adapters. Those adapters never qualify a production route. Without an admitted
route, keep the transcript in Review and report unavailability honestly. No
clipboard writes, artificial Send/Enter, UI automation, private endpoints, draft
sharing, model downloads or paid fallback are introduced.
